\section{Obsługa modułu radiowego}
Obsługa modułu radiowego realizowana jest poprzez autorską 
bibliotekę \texttt{ook\_433mhz} realizującą przesył i~odczyt
danych z~prostych nadajników radiowych używając metody
\textit{On--Off Keying} (OOK).
Biblioteka jest mocno inspirowana biblioteką
\texttt{RadioHead}, ze szczególnym naciskiem na zawartą w~niej 
klasę \texttt{RH\_ASK}.

Ten podrozdział jest poświęcony obsłudze nadajnika radiowego
(struktura \texttt{Transmitter} biblioteki \texttt{ook\_433mhz})
i~nie będzie zagłebiał się w~implementacje obsługi odbiornika.

\subsection{Przebieg transmisji}
Transmisję danych można podzielić na 3~etapy: synchronizację,
wysłanie bajtu startu i~wysłanie ramki danych.
Sygnał synchronizujący składa się z~3~bajtów wypełnionych 
naprzemiennie bitami o~wartościach~1~i~0 i~służy do 
przygotowania odbiornika na odczyt danych.
Bajt startu (zdefiniowany w~bibliotece stałą \texttt{START\_BYTE})
przyjmuje formę liczby o~zapisie binarnym \texttt{11001100}.
Struktura ramki obejmuje pole długości, zawierające informację 
o~liczbie przesyłanych bajtów, oraz następujące po nim 
dane właściwe.

Dane transmitowane są poczynając od najmłodszego bitu każdego bajtu.
Same bity podzielone są na próbki (nazywane w~programie angielskim słowem 
\textit{tick}) używane do sterowania linią danych nadajnika radiowego.
Każda próbka przyjmuje wartość 0~lub~1, identyczną co wartości bitu, który 
buduje.

\subsection{Maszyna stanów}
Struktura \texttt{Transmitter} posiada pole \texttt{state} określające obecny 
stan nadajnika, wybrany spośród pięciu wartości opisanych w~typie wyliczeniowym
\texttt{TxState} i~są to:
\begin{enumerate}
    \item \textbf{\texttt{Idle}} --- stan ustawiany jako domyślny i~osiągany
    w~momencie zakończenia transmisji.

    \item \textbf{\texttt{Syncing}} --- stan, podczas którego wysyłane są bajty 
    sygnału synchronizującego, przypisywany nadajnikowi w~momencie, gdy dane 
    w~buforze są gotowe do wysłania.
    
    \item \textbf{\texttt{SendingStartByte}} --- stan osiągany po wysłaniu wszystkich
    wymaganych bajtów synchronizacyjnych, w~którym nadajnik wysyła bajt startu.
    
    \item \textbf{\texttt{SendingData}} --- stan, w~którym nadajnik wysyła
    zawartość buforu, osiągany po wysłaniu bajtu startu.
    
    \item \textbf{\texttt{DataSent}} --- stan osiągany po wysłaniu całej zawartości
    bufora.
\end{enumerate}

\subsection{Struktura \texttt{Transmitter}}
Struktura \texttt{Transmitter}, pokazana na listingu~\ref{lst:transmitter_struct},
przechowuje informacje niezbędne do prawidłowego nadania danych i~określenia
obecnego stanu nadajnika.

Głównym zadaniem pól \texttt{bit\_index} oraz \texttt{byte\_index} jest okreslenie,
który bajt i~zawarty w~nim bit powinien być w~danym momencie wysyłany.

Pole \texttt{buffer} przechowuje zakodowane dane przeznaczone do wysłania.
Jego wielkość ograniczona jest przez stałą czasu kompilacji 
\texttt{MAX\_BUFFER\_SIZE}. Bufor inicjalizowany jest wartościami zerowymi
i~nie następuje jego czyszczenie podczas pracy nadajnika, jest on jedynie
nadpisywany nowymi wartościami, których długość określa pole 
\texttt{message\_bit\_length}. 

Struktura posiada również parametr typu generycznego \texttt{TICKS\_PER\_BIT}
określający ilość próbek potrzebnych na przesłanie jednego bitu. Parametr ten
określany jest w~czasie kompilacji.

\begin{lstlisting}[
    language=Rust, style=colouredRust, 
    caption={Struktura \texttt{Transmitter}},
    label={lst:transmitter_struct}
]
pub struct Transmitter<const TICKS_PER_BIT: u8, Pin: OutputPin> {
    buffer: [u8; MAX_BUFFER_SIZE],
    message_bit_length: usize,
    bit_index: usize,
    byte_index: usize,
    state: TxState,
    pub pin: Pin,
    ticks: u8,
}
\end{lstlisting}


\subsection{Przygotowanie danych, kodowanie 4b6b}
Kodowanie 4B6B \translation{4--bit/6--bit} to schemat kodowania liniowego, 
w~którym  każdej 4--bitowej grupie danych (16 możliwych kombinacji) przypisywana 
jest odpowiadająca jej 6--bitowa grupa kodowa (spośród 64 możliwych kombinacji). 
Dodanie dwóch nadmiarowych bitów pozwala na taki dobór sekwencji wyjściowych, 
aby spełniały one dwa warunki: ograniczały maksymalną liczbę kolejnych jedynek 
i~zer w~strumieniu (tzw. kodowanie RLL, ang. \textit{run-length limited}) oraz 
zapewniały zbalansowany ich udział \translation{DC balance}. 
Dzięki temu przesyłany sygnał zawiera regularne przejścia między stanami,
co ułatwia odbiornikowi odtworzenie zegara transmisji \translation{clock recovery}
bezpośrednio z~odbieranego sygnału, bez potrzeby przesyłania osobnego sygnału 
taktującego.

Za przygotowanie danych do nadania odpowiada metoda \texttt{send} struktury
\texttt{Transmitter}, przedstawiona na listingu~\ref{lst:transmitter_send}. 
Sprawdza ona czy bajty wysyłanej wiadomość, po zakodowaniu, zmieszczą się 
w~buforze. W~przypadku, gdy wiadomość jest zbyt długa, zostaje ona przycięta
do maksymalnej możliwej długości (określonej stałą \texttt{MAX\_MESSAGE\_LENGTH}).
Następnie jako pierwszy bajt bufora zapisywany jest rozmiar wiadomości w~bajtach
przed kodowaniem, kolejne bajty bufora uzupełnione są zawartością wiadomości.
Tak przygotowany bufor zawsze będzie przynajmniej w~połowie niewykorzystany,
co pozwala na zakodowanie jego zawartości metodą \texttt{encode\_in\_place} modułu
\texttt{data\_coding::radio\_head\_4b6b}
Ilość bitów zakodowanej ramki, gotowej do wysłania przez nadajnik,
określa się sumując ilość bajtów niezakodowanej wiadomości z~ilością
bajtów kodujących jej rozmiar, następnie mnożąc tą wartością przez 
stałą określającą narzut pochodzący z~kodowania zapisaną jako ilość bitów na bajt. 
Funkcja zwraca informację o~ilości bajtów zapisanych do bufora
w~celu umożliwienia wysłania większej ilości danych dzieląc je na 
wysyłane oddzielnie fragmenty.

\begin{lstlisting}[
    language=Rust, style=colouredRust, 
    caption={Metode \texttt{send} struktury \texttt{Transmitter}},
    label={lst:transmitter_send}
]
pub fn send(&mut self, bytes: &[u8]) -> Option<usize> {
    let n_bytes = if bytes.len() > MAX_MESSAGE_LENGTH {
        MAX_MESSAGE_LENGTH
    } else {
        bytes.len()
    };

    // Set message length as first byte
    self.buffer[0] = n_bytes as u8;
    // Populate buffer
    self.buffer[1..=n_bytes].copy_from_slice(&bytes[0..n_bytes]);

    self.message_bit_length = (n_bytes + 1) * 6 * 2;

    // Encode data
    match encode_in_place(&mut self.buffer, n_bytes + 1) {
        Ok(_) => {
            self.state = TxState::Syncing;
            Some(n_bytes)
        }
        Err(_) => None,
    }
}
\end{lstlisting}


\subsection{Obsługa maszyny stanów}
Struktura \texttt{Transmitter} udostępnia metodę \texttt{transmit} odpowiedzialną
za przechodzenie pomiędzy stanami, wywoływanie funkcji pośrednich obsługujących
poszczególne stany i~podtrzymanie stanu pinu na długość konieczną do wysłania
wszystkich próbek dla jednego bitu.
Funkcje pośrednie zwracają jeden z~trzech stanów, informując metodę 
\texttt{transmit} o~etapie wykonania swoich czynności lub o~wystąpieniu błędu.

Wywołanie metody transmit powinno zachodzić w~równych interwałach. W~środowisku
systemów wbudowanych dobrym sposobem osiągnięcia tego jest zastosowanie 
przerwań pochodzących z~liczników mikrokontrolera.
